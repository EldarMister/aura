# Бильярд Cчетчик

Мобильное приложение для управления бильярдным залом и вывода табло на телевизор.
Проект сделан на **React Native + Expo + TypeScript**. Данные хранятся локально на
устройстве через `AsyncStorage`, а при включённой синхронизации передаются на ТВ через
облако или напрямую по локальной Wi-Fi сети.

## Что умеет проект

- Управлять двумя бильярдными столами.
- Открывать игру на выбранном столе с нужным тарифом.
- Автоматически считать прошедшее время и стоимость игры по цене за час.
- Ставить игру на паузу и продолжать её без начисления времени за паузу.
- Менять тариф у уже открытой игры.
- Добавлять напитки в текущую игру.
- Считать итог: время стола + напитки.
- Закрывать игру и сохранять её в историю.
- Отменять игру; отменённые игры попадают в историю, но не дают выручку.
- Показывать подробную карточку игры: стол, тариф, время, напитки, суммы.
- Вести порядковый номер игры.
- Показывать статистику за день, неделю и месяц.
- Считать проданные напитки, количество завершённых игр и общую выручку.
- Показывать разбивку игр по столам.
- Открывать список всех игр за выбранный период.
- Редактировать справочник напитков: название и цена.
- Редактировать справочник тарифов: название и цена за час.
- Подключать телевизор как отдельное табло.
- Показывать на ТВ два стола, статус, тариф, прошедшее время, сумму и напитки.
- Работать с ТВ через облачный `socket.io` сервер.
- Работать с ТВ напрямую по Wi-Fi без интернета через TCP.
- Сохранять настройки, тарифы, напитки, текущие столы, историю и подключение между запусками.
- Запускаться как Expo-приложение для разработки.
- Собираться в Android APK для установки на телефон или ТВ.

## Синхронизация с ТВ

Есть два режима связи:

- **Облако**: телефон и ТВ подключаются к одному `socket.io` серверу и одной комнате.
  Работает в Expo Go и в APK.
- **Локально (Wi-Fi)**: ТВ поднимает TCP-сервер и показывает свой IP, телефон подключается
  к этому IP. Для этого нужен dev/EAS/APK билд, потому что используется нативный модуль
  `react-native-tcp-socket`.

Роли устройств:

- **Пульт** (`controller`) - основное устройство, где открывают и закрывают игры.
- **Табло** (`display`) - ТВ, которое принимает снимок состояния и показывает его read-only.

Пульт отправляет на табло снимок столов, тарифов, напитков, истории и счётчика игр.
На практике ТВ использует для отображения только текущие столы, тарифы и напитки.

## Поведение после перезапуска

Состояние сохраняется в `AsyncStorage` под ключом `billiard-store-v1`.

Сохраняется:

- выбранный стол;
- текущие состояния столов и открытые игры;
- тарифы;
- напитки;
- история игр;
- счётчик номеров игр;
- настройки подключения к ТВ.

Не сохраняется текущий экран приложения (`screen`). После обычного запуска приложение
открывается на экране управления столами. Но если устройство сохранено в настройках как
роль **Табло** (`connection.role = display`), приложение после восстановления состояния
автоматически переходит на экран ТВ.

Итог: на ТВ не нужно каждый раз вручную заходить на табло, если в настройках этого
устройства выбрана роль **Табло**. Если просто открыть экран ТВ вручную на устройстве,
которое остаётся ролью **Пульт**, после перезапуска откроется главный экран.

## Облачный сервер

Сервер находится в папке `server/`. Он принимает live-состояние через `socket.io`.

Без `DATABASE_URL` сервер хранит состояние только в памяти:

```bash
npm run server:install
npm run server:start
```

Для продакшена задайте переменные окружения:

```bash
PORT=3000
DATABASE_URL=postgresql://user:password@host:5432/database
```

При старте сервер создаёт таблицу `cloud_state`, если её ещё нет:

```sql
create table if not exists cloud_state (
  room text primary key,
  snapshot jsonb not null,
  updated_at timestamptz not null default now()
);
```

В `snapshot` лежит весь снимок состояния заведения: столы, тарифы, напитки, история игр
и счётчик игр. Чтобы очистить только тестовую историю игр, не трогая тарифы и напитки,
достаточно обнулить поля `snapshot.history` и `snapshot.gameCounter`.

## Переменные окружения приложения

В корневом `.env` можно задать облачный сервер и комнату:

```bash
EXPO_PUBLIC_SYNC_URL=https://your-sync-server.example.com
EXPO_PUBLIC_SYNC_ROOM=club-1
```

Если `EXPO_PUBLIC_SYNC_URL` задан, приложение использует этот URL для облачного режима.

## Важная логика данных

- Справочники тарифов и напитков живут отдельно от истории игр.
- В истории игры сохраняется снимок тарифа и напитков на момент закрытия игры.
- Выручка в статистике считается только из завершённых игр (`status = completed`).
- Отменённые игры (`status = canceled`) видны в истории, но не добавляют выручку.
- Проданные напитки и выручка по напиткам в статистике считаются из `history`.
- Очистка `history` удаляет статистику прошлых игр и продаж напитков из этих игр, но не
  удаляет сами напитки из справочника.
